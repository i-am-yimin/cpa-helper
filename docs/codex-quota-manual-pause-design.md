# Codex 低额度暂停与自动恢复

2026-11-09 调整：巡检确认额度恢复后，自动恢复原优先级和路由，替代此前必须手动解除额度暂停的行为。

## 额度判断

- 5 小时或周剩余额度达到设置的下限（`remaining <= threshold`），任一命中即暂停路由并将优先级设为 `-1`。
- 所有已配置窗口均取得有效的新鲜额度，且剩余值严格高于下限后，自动恢复。仅一个窗口恢复、额度查询失败、缺少窗口、未知窗口或观察过期时继续暂停。
- 按实际窗口时长识别 5 小时与周配额，不将所有 primary 窗口视为 5 小时。`0%` 是有效下限，取消勾选表示关闭窗口规则。
- 关闭规则本身不立即启用凭证。后续巡检仍会核实原触发窗口是否高于暂停时的下限；确认恢复后可自动恢复，也可以使用显式手动恢复入口。

## 恢复优先级与其他禁用原因

恢复值按以下顺序选择：已保存的手动优先级、暂停前优先级、当前套餐默认值；均缺失时使用 `0`。`0` 是正常优先级，`-1` 是暂停保留值，不能作为恢复值。

暂停前通过 CPA 设置的非套餐默认值也会保留，避免自动恢复后被下一轮巡检覆盖。手动指定的值继续生效；管理员可以显式切回套餐默认值。

额度暂停、人工禁用和凭证失效独立记录。自动恢复不解除人工禁用，不会启用仍然无效的凭证。无额度暂停状态的普通禁用凭证不通过本流程自动启用。凭证失效后，必须重新查询并确认健康和额度都恢复，才可恢复由额度引发的暂停。

## 状态与远端同步

`codex_quota_policies` 保存阈值、暂停原因和时间、触发窗口及下限、暂停前优先级、人工禁用、凭证异常、手动优先级、额度观察和同步结果。继续使用既有 JSON 状态，不新增数据库迁移。

| 事件 | 额度暂停状态 | 路由与优先级 |
| --- | --- | --- |
| 任一有效窗口命中下限 | 置为暂停 | 先禁用路由，再写入 `-1` 并回读确认 |
| 所有已配置窗口恢复且凭证健康 | 同步成功后解除暂停 | 先恢复优先级并回读确认，再启用路由并回读确认 |
| 人工禁用尚未解除 | 保留暂停 | 保持禁用 |
| 查询失败、字段缺失、窗口未知或过期 | 保留暂停 | 保持禁用与 `-1` |
| 恢复写入或回读失败 | 保留暂停及恢复值，记录同步错误 | 尝试重新禁用和写回 `-1`，后续巡检重试 |
| 自动恢复成功 | 清除旧暂停原因、触发窗口、时间和恢复快照 | 记录“额度恢复”及恢复后的优先级 |
| 恢复后再次命中阈值 | 重新暂停并记录新的触发信息 | 保存当前优先级供下次恢复 |
| 服务重启 | 保留持久状态 | 取得新的有效额度后再判断是否恢复 |

检查、手动修改、启停和恢复共用每凭证串行锁；全局规则变更与单凭证操作互斥。暂停不能仅凭优先级正负推断，实际通过 CPA 的 `disabled` 状态阻止选路，避免负优先级凭证成为最后兜底候选。

独立后台任务每 30 秒启动一轮检查，最多 4 个并发，不受自动巡检开关或旧的 10 分钟巡检缓存阻止。额度暂停的凭证继续查询额度。实际延迟还包括排队和上游响应时间，已开始的请求不强制中断。显式配置的额度规则会实际执行，不受旧巡检模拟开关影响。

## 管理界面

- 全局入口：**上游与凭证 → 巡检与默认规则 → Codex 低额度暂停**。
- 单凭证入口：**全部上游 → Codex → 设置额度暂停规则**，支持继承、单独设置和关闭。
- 暂停期间显示最新剩余额度，历史触发原因与当前额度分开呈现。提示额度恢复后自动恢复原优先级与路由。
- 保留“保存并恢复路由”操作。显式手动恢复仍要求指定有效优先级，查询最新健康与额度，不能绕过仍命中的阈值或人工禁用。
- 普通启停、优先级修改、凭证字段编辑和重新上传继续保留暂停保护。

## 验证

后台回归覆盖正常巡检及独立后台检查、5 小时与周窗口联合判断、阈值边界、字段缺失与过期、健康恢复、人工禁用、零优先级和手动高优先级、历史优先级缺失时的套餐回退、同步失败回滚与重试、重复暂停、并发修改及显式恢复入口。

前端回归覆盖暂停时显示当前额度、自动刷新后的恢复状态、恢复优先级、规则文案以及手动恢复不能绕过阈值。
