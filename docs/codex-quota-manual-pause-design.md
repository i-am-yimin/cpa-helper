# Codex 低额度暂停路由设计

状态：已实现并部署至生产，代码 `544b67e`；[构建与部署记录](https://github.com/i-am-yimin/cpa-helper/actions/runs/42519174069) 通过。管理员尚需按实际需求配置并启用阈值。

## 目标与现状

Codex 的 5 小时或周窗口剩余额度达到设置的下限后，持续停止这份凭证的后续路由。必须显式手动恢复，不因额度回升、窗口重置、OAuth 刷新或服务重启自动恢复。

阈值仍命中时，手动调高优先级不能绕过规则；后续巡检继续维持暂停，不设置当前窗口豁免。

改造前的 `applyKeeperPriorityPolicy` 在额度恢复后自动回写优先级；CPA 选路也允许负优先级凭证成为最后的候选。因此仅删除自动恢复分支或仅写入暂停优先级，都不足以保证停止路由。现在通过 CPA 的禁用状态阻止实际选路，套餐默认值由独立的 `applyKeeperPlanPriority` 处理。

确认暂停优先级为 `-1`，下文记为 `paused_priority`。路由资格由独立暂停状态决定，不靠优先级正负推断。

## 阈值配置

- 分别配置「5 小时剩余额度 ≤ X%」和「周剩余额度 ≤ Y%」，任一命中即触发暂停。
- 明确显示“剩余”，不复用现有含义不清的“额度阈值”标签；内部如沿用已用比例，须转换为 `used >= 100 - remaining_threshold`。
- 每份凭证可选择继承全局规则、单独设置、关闭本凭证规则。“取消阈值”需要明确关闭规则，不能用 `0%` 表示关闭，因为真实剩余 `0%` 仍是有效触发值。
- 仅使用有效且新鲜的额度观察；失败、字段缺失、未知窗口和过期观察不当成 0。按实际窗口标识判断，不能把所有 primary 窗口视为 5 小时。

## 持久暂停与路由执行

独立持久化 `quota_paused`、触发窗口及其重置时间、触发时剩余值/阈值、触发时间、原优先级、手动指定优先级、规则模式、操作版本及同步结果。暂停记录不随 quota 缓存过期而失效，也不使用随 OAuth 刷新变化的 token/更新时间作为凭证身份。

暂停生效时，同时要求：

1. 本地记录额度暂停意图。
2. 将 CPA 中该凭证设为 `disabled=true`，使其从实际候选中排除。
3. 将显示/远端优先级同步为 `paused_priority`，记录同步完成。

使用 Core 的禁用资格阻断，可覆盖普通选路、兜底、重试与会话绑定，并且不依赖分组插件或快照是否在线。不能在候选全部暂停时重新回退选中它们。

额度暂停、人工禁用和凭证失效分别记录。解除额度暂停不能清掉其他禁用原因。界面显示“额度触发暂停”，不把它冒充凭证失效。

## 状态转换

| 事件 | 额度暂停状态 | 实际路由 |
| --- | --- | --- |
| 有效观察首次命中任一阈值 | 置为暂停并同步 CPA | 同步成功后不再被选中 |
| 额度回升或窗口重置 | 保持暂停 | 不自动恢复 |
| 阈值仍命中，管理员修改普通优先级 | 保持暂停，保留操作说明；不临时启用 | 继续阻断，巡检继续维护暂停优先级 |
| 取消阈值规则 | 暂停仍保留，显示可以手动恢复 | 不因改配置自行放行 |
| 管理员指定可用优先级并恢复，且规则已关闭或新鲜额度已安全 | 解除额度暂停 | 无其他禁用原因时恢复 |
| 刷新额度失败、服务重启或重新部署 | 保留原暂停记录 | 继续阻断 |

额度尚低且规则有效时，恢复操作应直接说明仍由哪条阈值规则阻断，不出现“保存成功后短暂放行，下一次巡检再暂停”的时间缝隙。

正常手动恢复必须使用显式指定的优先级；不能被下一轮套餐默认规则覆盖。需要将“使用套餐默认值”和“手动指定值”作为不同模式持久化。普通优先级可以为 0；暂停优先级不是恢复值。

## 同步与监测

- 检查、手动修改、启停和恢复共用每凭证串行锁及操作版本，避免旧巡检结果覆盖较新的管理员操作。
- 暂停先禁用再改优先级；恢复先设置目标优先级，再确认其他阻断均已解除，最后启用。两者都需要远端回读/确认和幂等重试。
- 同步失败显示“暂停同步失败/待同步”，不能提前宣称已停止路由。已确认的暂停状态不能因网络失败或过期快照被清除。
- 额度策略使用独立的短周期检查与请求合并，建议 30–60 秒；不能直接被现有 10 分钟自动巡检缓存跳过。策略暂停的凭证仍可查询额度，但查询恢复健康不能触发自动启用。
- 能保证的是“检测并确认暂停后，不再选择该凭证处理后续请求”。阈值判断存在巡检与上游额度更新延迟，已开始的请求/流不强行中断。

## 管理界面

在“上游与凭证”的 Codex 行显示暂停状态、触发原因、暂停优先级和最近观察/同步时间；展开可查看具体窗口、阈值和操作记录。

提供“保存优先级并恢复路由”操作。额度仍命中时明确阻断并指向该凭证的阈值设置；规则关闭后可以在同一流程中指定恢复值。普通启用开关、单条/批量刷新和直接优先级编辑都必须走同一恢复校验，避免出现旁路。

## 改动范围与验收

改动范围包括 Keeper 阈值/自动恢复策略、手动优先级和启停入口、持久暂停及同步状态、独立检查调度和统一管理页。SQLite、PostgreSQL 及导入清单同步迁移。规则范围仅为 Codex，保留已有 Antigravity 分组规则。

关键验收：5h/周分别命中、等于边界、窗口缺失/过期、额度恢复不自动启用、重启后仍暂停、手动高优先级仍受规则约束、关闭阈值不自行放行、手动恢复值不被套餐规则覆盖、所有候选暂停时不兜底选中、会话/重试不绕过、远端写入失败及管理员/巡检并发。

升级时不把历史所有负优先级或 `-1` 一律认作新规则暂停；先区分已有状态和显式启用的新规则，防止升级时误停其他凭证。

## 实现与使用

- 全局入口：**上游与凭证 → 巡检与默认规则 → Codex 低额度暂停**。初次升级默认关闭，管理员可选择 5 小时、周剩余下限；未代用户设定百分比。
- 单凭证入口：**全部上游 → Codex → 设置额度暂停规则**，支持继承、单独设置和关闭。取消勾选关闭某个窗口，`0%` 是有效下限。
- 恢复入口：在该行输入明确的恢复优先级，点击“保存并恢复路由”。后台重新查询健康和额度；仍命中时返回冲突并继续禁用，没有临时放行。
- 普通优先级修改、启用开关、凭证字段编辑和认证文件重新上传均保留额度暂停保护。重新上传的凭证内容会保留已有禁用与 `-1`；暂停不依赖浏览器或插件心跳。
- `codex_quota_policies` 持久化规则、暂停、触发窗口/下限/重置时间、人工禁用、凭证异常、手动优先级、观察及同步结果。SQLite、PostgreSQL、导入清单和启动就绪版本一起升级为 `202611090001`。
- 独立后台任务每 30 秒启动一轮检查，最多 4 个并发；实际检测延迟还包含排队及上游响应时间。所有同凭证的策略检查和管理操作共用锁；全局规则变更与恢复操作互斥。失败暂停意图保留，后续轮次先重试阻断再查询额度。
- 新规则实际执行，不受旧巡检模拟开关影响；界面对此明确提示。既有 Antigravity 已用阈值保留在独立标明的设置中。
- 旧巡检终态日志在标记任务完成前落盘；关闭应用会等待自动、条件及手动刷新任务结束，再关闭数据库，避免刷新收尾越过存储生命周期。

核心实现：`backend/internal/app/codex_quota_policy.go`；交互：`CodexQuotaPolicyEditor.vue` 和统一管理页。回归覆盖边界、未知/过期窗口、暂停持久化、零优先级、同步失败、并发、管理员权限、缺失恢复值和关闭规则不放行。
